# Rogue-Go — консольная roguelike-игра на Go

Командный учебный проект School 21 (Школы 21): исследование процедурно
сгенерированных подземелий, сражения с противниками и управление инвентарём.
Сданная учебная версия от 29 сентября 2025 года.

## Возможности

В исходниках реализованы:

- Генерация комнат и коридоров, переходы между уровнями, цель пройти 21 уровень.
- Движение, бой, характеристики персонажа и поведение шести типов противников:
  зомби, вампира, призрака, огра, змея-мага и мимика.
- Оружие, пища, зелья, свитки, сокровища, цветные ключи и двери.
- Инвентарь, временные эффекты и подстройка сложности по состоянию персонажа.
- Сохранение и загрузка состояния в JSON, автосохранение при переходе на
  следующий уровень в `last_session.json`, статистика в `statistics.json`.
- Классический 2D-режим: символьная карта, видимость и туман войны.
- Экспериментальный псевдо-3D-режим: ray casting (DDA), стены, спрайты
  объектов, мини-карта и панели состояния.

Это перечень по коду, а не утверждение о полном функциональном тестировании.
Фактически выполненные проверки перечислены ниже.

## Архитектура

```text
.
├── cmd/rogue/                 # Точка входа и связывание слоёв
├── internal/
│   ├── data/repo/             # JSON-хранилище сохранений и статистики
│   ├── domain/
│   │   ├── entity/            # Игровые сущности и состояние
│   │   ├── gen/               # Генерация подземелий
│   │   ├── rules/             # Бой, движение, инвентарь, видимость, камера
│   │   ├── utils/             # Вспомогательные функции
│   │   ├── game.go            # Фасад игры
│   │   └── ports.go           # Интерфейс хранилища
│   └── presentation/          # ncurses, ввод, меню, 2D/3D-рендеринг
├── go.mod
├── go.sum
└── Makefile
```

Точка входа связывает игру, JSON-хранилище и терминальный интерфейс.
Игровые правила работают с общим состоянием, а слой представления вызывает
действия через фасад игры. Модуль `rogue-go` находится в корне репозитория.

## Требования

- Linux или WSL с терминалом, поддерживающим ncurses и UTF-8.
- Go 1.24.3 или новее; директива в `go.mod` — `go 1.24.3`.
- C-компилятор, `pkg-config`, заголовки и библиотеки ncurses, `make`.
- Включённый CGO (`go env CGO_ENABLED` должен выводить `1`).
- Локаль `ru_RU.UTF-8`: её запрашивает точка входа через библиотеку SetLocale.

Для Ubuntu системные зависимости устанавливаются отдельно:

```bash
sudo apt update
sudo apt install build-essential pkg-config libncurses-dev locales
sudo locale-gen ru_RU.UTF-8
```

Эти команды не устанавливают Go. Наличие локали можно проверить через
`locale -a`, а ncurses — через `pkg-config --modversion ncurses ncursesw`.
Первой сборке нужен доступ к Go module proxy для закреплённых зависимостей
`goncurses` и `SetLocale`; их версии и контрольные суммы находятся в модуле.

Для запуска используйте достаточно большой терминал. Проверка проводилась
при 140 столбцах и 40 строках с `TERM=xterm-256color`; широкий стартовый баннер
на небольшом экране может обрезаться.

## Сборка и запуск

Из корня репозитория:

```bash
make build
make run
```

`make build` создаёт `build/rogue`; повторный вызов безопасен. `make run`
пересобирает приложение и запускает этот файл в текущем терминале.
Для отдельного запуска после сборки используйте `./build/rogue`.

```bash
make clean
```

`clean` удаляет только `build/rogue`. Каталог `build/`, другие файлы в нём,
сохранения, статистика и `go.sum` сохраняются. Сборка использует
`-mod=readonly` и не запускает `go mod tidy` автоматически.

Сохранения с относительным именем записываются в текущий рабочий каталог.
В диалоге сохранения задайте, например, `my-game.json`; он записывает в
указанный файл, поэтому для разных сеансов используйте разные имена.
Корневые `*.json` и `*.sav` исключены из Git. Сохранения с другими именами или
в других каталогах требуют отдельного правила исключения.

## Управление

В меню используйте `↑` / `↓` и `Enter`. После стартового экрана и выбора новой
игры приложение просит нажать любую клавишу.

| Действие | Клавиши |
|---|---|
| Движение в 2D | `W/A/S/D` или стрелки |
| Переключить 2D ↔ 3D | `T` |
| Движение вперёд / назад в 3D | `W/S` или `↑` / `↓` |
| Боковой шаг в 3D | `A/D` |
| Поворот в 3D | `←` / `→` |
| Показать / скрыть мини-карту в 3D | `M` |
| Инвентарь | `I` |
| Подобрать предмет на клетке игрока | `P` |
| Оружие / пища / зелье / свиток или ключ | `H` / `J` / `K` / `E` |
| Взаимодействие с ближайшим объектом в 3D | `Пробел` / `Enter` |
| Сохранить / загрузить игру в 2D | `V` / `O` |
| Меню выхода в 2D | `Q` |
| Меню выхода в 3D | `Esc` |

В списке предметов выбор выполняется цифрами; `0` в меню оружия снимает его.
Для сохранения или загрузки из 3D сначала переключитесь в 2D.
После выхода из сессии, начатой через `NEW GAME`, снова показываются
стартовый экран и главное меню. После сессии, открытой через `CONTINUE`
или `LOAD GAME`, приложение возвращается непосредственно в главное меню,
без стартового экрана. Для завершения процесса выберите `EXIT GAME`
в главном меню.

Таблица составлена по обработчикам ввода. Проверка каждой клавиши и всех
игровых ситуаций не проводилась.

## Проверки и ограничения

8 ноября 2026 года на Linux/amd64 с Go 1.24.3 выполнены
`go vet ./...`, `go test ./...`, `go mod verify` и сборка через Makefile.
Три автоматических теста проверяют JSON-сохранение состояния, ошибки чтения
и добавление/сортировку статистики; остальные пакеты пока не имеют тестов.

В интерактивном TTY проверены меню, создание игры, два шага в 2D,
переключение 2D/3D, включение и выключение мини-карты, открытие инвентаря,
ручное сохранение/загрузка и выход с кодом 0. Это короткая проверка запуска;
полное прохождение, бой, все предметы, переходы уровней и баланс не проверены.

Известные ограничения сданной версии:

- Псевдо-3D экспериментален. Подсказка HUD о мыши и `E:Inventory` не соответствует
  обработчикам: поворот — стрелками, инвентарь — `I`. Обработчики `Q/R` меняют
  `PlayerAngle`, тогда как рендер использует `PlayerDir`; быстрые повороты
  не следует считать рабочей возможностью.
- Обработчик взаимодействия в 3D ищет соседний предмет, но вызывает подбор
  с текущей клетки. Подбор соседних предметов этим способом не гарантирован.
- Размеры окон вычисляются при инициализации. Маленькие терминалы и изменение
  размера окна во время игры не проверены; защиты от всех таких случаев нет.
- Загрузка JSON не проверяет полноту игрового состояния. Используйте собственные
  сохранения этой версии: корректный по синтаксису, но неполный JSON может
  привести к ошибке во время игры. Совместимость сохранений с ранним прототипом
  не подтверждена.
