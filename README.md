# Rogue-Go

**Консольная roguelike-игра на Go с процедурной генерацией подземелий, сражениями и двумя режимами отображения — 2D и псевдо-3D.**

Командный учебный проект School 21, разработанный участниками `4vertak` и `objectte`. В репозитории представлена версия, завершённая 29 сентября 2025 года, с сохранённой историей командной разработки.

## Об игре

Rogue-Go — игра об исследовании процедурно генерируемых подземелий. Игрок
перемещается между комнатами по коридорам, встречает противников, собирает
сокровища и предметы, подбирает оружие и использует содержимое инвентаря.
Задача — сохранить здоровье и пройти 21 уровень, находя выход на каждом этаже.

В классическом 2D-режиме подземелье показано символьной картой с туманом войны:
по мере исследования открываются комнаты и проходы. Экспериментальный
псевдо-3D-режим показывает ту же карту от первого лица — со стенами, спрайтами
объектов и мини-картой. Между режимами можно переключаться во время игры.

## Основные возможности

### Генерация подземелий

- Комнаты случайного размера и положения размещаются в сетке 3×3 и соединяются
  коридорами.
- На каждом уровне определяются стартовая комната и комната с выходом.
- Комнаты заполняются противниками и предметами с учётом номера уровня
  и текущей сложности.
- Начиная со второго уровня генерируются цветные двери и соответствующие ключи.

### Игровая механика

- Перемещение по клеткам, сражения и характеристики персонажа: здоровье,
  сила и ловкость.
- Инвентарь с оружием, пищей, зельями, свитками и ключами; сбор сокровищ.
- Временные эффекты и изменение характеристик при использовании предметов.
- Подстройка сложности по состоянию персонажа, влияющая на наполнение
  следующих уровней.
- Панели состояния, игровые сообщения и таблица результатов.

### Противники

В игре реализованы шесть типов противников: зомби, вампир, призрак, огр,
змей-маг и мимик. Их характеристики задаются при генерации, а правила
движения, преследования и боя вынесены в игровой слой.

### Сохранение прогресса

Состояние игры сохраняется в JSON и загружается через меню. При переходе
на следующий уровень создаётся автосохранение `last_session.json`.
Пункт `CONTINUE` открывает этот файл, а `LOAD GAME` позволяет указать другое
сохранение. Результаты игровых сессий записываются в `statistics.json`.

Для ручных сохранений можно использовать разные имена, например
`my-game.json`. Относительные пути отсчитываются от каталога запуска игры;
повторное сохранение с тем же именем перезаписывает файл.

## Техническая реализация

Игра написана на Go 1.24.3. Терминальный интерфейс работает через `goncurses` —
обёртку над ncurses, поэтому для сборки необходимы CGO и C-компилятор.
Библиотека SetLocale задаёт локаль терминала.

Генератор строит клеточную карту размером 80×35. Планировщик коридоров работает
с графом комнат: строит остов по расстояниям между ними, использует систему
непересекающихся множеств (DSU) для учёта связности и добавляет дополнительные
соединения. Размещение противников, предметов, дверей и ключей выполняется
после создания комнат и проходов.

Игровое состояние объединено в `GameState`: персонаж, уровень, противники,
инвентарь, эффекты, прогресс и статистика. Фасад `Game` связывает генерацию,
правила игры и операции сохранения. После обработки ввода обновляются
видимость, противники, эффекты и условия завершения игры.

2D-интерфейс отображает карту и игровые сущности символами. Псевдо-3D использует
ray casting: для столбцов экрана выпускаются лучи, а алгоритм DDA последовательно
проверяет клетки до пересечения со стеной или закрытой дверью. Расстояние
определяет высоту отображаемой стены. Противники и предметы рисуются спрайтами,
для ориентации служит мини-карта. Это экспериментальное представление клеточной
карты, а не полноценный 3D-движок.

JSON-хранилище использует стандартный пакет `encoding/json`. Зависимости
закреплены через Go modules в `go.mod` и `go.sum`, сборка и запуск оформлены
в Makefile. Автоматические тесты написаны на Go с пакетом `testing`.

## Архитектура проекта

```text
.
├── cmd/rogue/                 # Точка входа и связывание слоёв
├── internal/
│   ├── domain/                # Фасад Game и интерфейс хранилища
│   │   ├── entity/            # Сущности, характеристики и GameState
│   │   ├── gen/               # Генерация комнат, коридоров и наполнения
│   │   ├── rules/             # Движение, бой, предметы, эффекты и видимость
│   │   └── utils/             # Вспомогательные функции
│   ├── data/repo/             # JSON-сохранения, статистика и тесты хранилища
│   └── presentation/          # Ввод, меню, окна ncurses и 2D/3D-отрисовка
├── go.mod
├── go.sum
└── Makefile
```

`cmd/rogue` создаёт хранилище, игру и интерфейс. Слой `presentation` принимает
ввод, вызывает действия через `Game` и отображает состояние. Игровые правила
работают с сущностями из `domain/entity`, а `domain/gen` создаёт новые уровни.
Сохранение и загрузка выполняются через интерфейс хранилища, реализация
которого находится в `data/repo`.

## Сборка и запуск

Требуется Linux или WSL с UTF-8-терминалом, Go 1.24.3, C-компилятор,
`pkg-config`, `make` и библиотеки разработки ncurses. CGO должен быть включён:
`go env CGO_ENABLED` должен выводить `1`. Игра запрашивает локаль `ru_RU.UTF-8`.

Установка системных зависимостей в Ubuntu:

```bash
sudo apt update
sudo apt install build-essential pkg-config libncurses-dev locales
sudo locale-gen ru_RU.UTF-8
```

Go устанавливается отдельно. Проверить наличие локали можно командой
`locale -a`, а ncurses — `pkg-config --modversion ncurses ncursesw`.

Клонирование, сборка и запуск:

```bash
git clone https://github.com/4vertak/rogue-go.git
cd rogue-go
make build
make run
```

При первой сборке Go загружает зависимости, если их нет в локальном кэше.
Готовый файл находится в `build/rogue`; после сборки его можно запустить
командой `./build/rogue`. `make clean` удаляет этот файл, сохраняя пользовательские
сохранения, статистику и `go.sum`.

Рекомендуется терминал размером не менее 140 столбцов и 40 строк — в таком
размере игра проверялась с `TERM=xterm-256color`. На небольшом экране стартовый
баннер и элементы интерфейса могут обрезаться.

## Управление

В меню используются `↑` / `↓` и `Enter`. После стартового экрана и выбора
новой игры нужно нажать любую клавишу.

| Действие | Клавиши |
|---|---|
| Движение в 2D | `W/A/S/D` или стрелки |
| Переключить 2D ↔ 3D | `T` |
| Движение вперёд / назад в 3D | `W/S` или `↑` / `↓` |
| Боковой шаг в 3D | `A/D` |
| Поворот в 3D | `←` / `→` |
| Показать / скрыть мини-карту в 3D | `M` |
| Инвентарь | `I` |
| Подобрать предмет на клетке игрока | `P` |
| Оружие / пища / зелье / свиток или ключ | `H` / `J` / `K` / `E` |
| Взаимодействие с ближайшим объектом в 3D | `Пробел` / `Enter` |
| Сохранить / загрузить игру в 2D | `V` / `O` |
| Меню выхода в 2D | `Q` |
| Меню выхода в 3D | `Esc` |

Предметы в списках выбираются цифрами; `0` в меню оружия снимает его.
Для сохранения или загрузки из псевдо-3D сначала переключитесь в 2D.

После выхода из сессии, начатой через `NEW GAME`, снова показываются стартовый
экран и главное меню. После `CONTINUE` или `LOAD GAME` приложение возвращается
непосредственно в главное меню. Для завершения процесса выберите `EXIT GAME`
в главном меню.

## Тестирование и ограничения

На Linux/amd64 с Go 1.24.3 выполнены проверки:

```bash
go test ./...
go vet ./...
make build
```

Три теста JSON-хранилища проверяют сохранение и восстановление состояния,
ошибки чтения и добавление/сортировку результатов. Короткий интерактивный
прогон охватывал новую игру, движение в 2D, переключение режимов, мини-карту,
инвентарь, ручное сохранение/загрузку и выход через меню. Полное прохождение
и все игровые ситуации не проверялись.

У сданной учебной версии остаются ограничения:

- Псевдо-3D экспериментален. Подсказки HUD о мыши и `E:Inventory` неточны:
  поворот выполняется стрелками, инвентарь открывается через `I`.
  Быстрые повороты `Q/R` меняют `PlayerAngle`, но рендер использует `PlayerDir`.
- Взаимодействие через `Пробел` / `Enter` ищет соседний предмет, тогда как
  подбор работает на текущей клетке игрока.
- Окна рассчитываются при инициализации. Маленькие терминалы и изменение
  размера окна во время игры не проверены и могут нарушать отображение.
- Загрузка JSON не проверяет полноту игрового состояния. Синтаксически
  корректный, но неполный файл может привести к ошибке во время игры.
  Используйте сохранения этой версии; совместимость со старыми не подтверждена.
