# Rogue-Go

**Консольная roguelike-игра на Go с процедурной генерацией подземелий, пошаговыми сражениями и двумя режимами отображения — 2D и псевдо-3D.**

Командный учебный проект [School 21](https://21-school.ru/), разработанный участниками `4vertak` и `objectte`. В репозитории представлена версия, завершённая 29 сентября 2025 года, с сохранённой историей командной разработки.

## Об игре

Rogue-Go — игра об исследовании подземелий, в которой каждый уровень формируется процедурно.

Игрок перемещается между комнатами и коридорами, встречает противников, собирает оружие и другие предметы, управляет ресурсами и пытается пройти 21 уровень.

По мере прохождения меняются условия и сложность игры. Для выживания необходимо учитывать характеристики персонажа, особенности противников и доступные предметы.

Игра поддерживает два способа отображения одного игрового мира:

- **2D** — классическая символьная карта с ограниченной видимостью и туманом войны.
- **Псевдо-3D** — экспериментальное представление от первого лица с использованием ray casting и мини-карты.

## Основные возможности

### Генерация подземелий

- Процедурное создание комнат и коридоров.
- Формирование связей между помещениями.
- Переходы между уровнями.
- Последовательность из 21 уровня.

### Игровая механика

- Передвижение и взаимодействие с окружением.
- Сражения с учётом характеристик персонажа и противников.
- Управление оружием и инвентарём.
- Использование пищи, зелий и свитков.
- Сбор сокровищ.
- Цветные ключи и двери.
- Временные эффекты и изменение сложности в зависимости от состояния персонажа.

### Противники

Реализовано шесть типов противников:

- Зомби.
- Вампир.
- Призрак.
- Огр.
- Змей-маг.
- Мимик.

Противники отличаются характеристиками и особенностями поведения. В частности, мимик способен маскироваться под предмет.

### Сохранение прогресса

Игровое состояние сохраняется в формате JSON.

Реализованы ручное сохранение и загрузка, автосохранение при переходе на следующий уровень и запись игровой статистики.

## Техническая реализация

Проект написан на **Go**. Для терминального интерфейса используется `ncurses` через Go-библиотеку `goncurses`.

Основные технические компоненты:

| Компонент | Реализация |
|---|---|
| Язык | Go 1.24.3 |
| Интерфейс | ncurses / goncurses |
| Генерация уровней | Комнаты, коридоры и переходы |
| Игровые правила | Движение, бой, предметы, противники |
| 2D-отображение | Символьная карта и туман войны |
| Псевдо-3D | Ray casting с DDA |
| Хранение данных | JSON |
| Сборка | Makefile, Go modules |
| Тестирование | Go testing |

### Псевдо-3D-режим

Помимо классической карты, в проекте реализован экспериментальный режим отображения от первого лица.

Для построения изображения используется алгоритм ray casting с обходом сетки методом DDA (*Digital Differential Analyzer*).

Режим включает отображение стен, спрайтов игровых объектов, мини-карту и элементы интерфейса с информацией о состоянии персонажа.

Оба режима работают с общим игровым состоянием.

## Архитектура проекта

Код организован с разделением игровой логики, хранения данных и терминального представления.

```text
rogue-go/
├── cmd/
│   └── rogue/                 # Точка входа
│
├── internal/
│   ├── domain/                # Игровая логика
│   │   ├── entity/            # Сущности и состояние игры
│   │   ├── gen/               # Генерация подземелий
│   │   ├── rules/             # Игровые правила
│   │   ├── utils/             # Вспомогательные функции
│   │   ├── game.go            # Фасад игры
│   │   └── ports.go           # Интерфейсы хранилища
│   │
│   ├── data/
│   │   └── repo/             # JSON-хранилище
│   │
│   └── presentation/          # Терминальный интерфейс
│
├── go.mod
├── go.sum
├── Makefile
└── README.md
```

**Domain** содержит игровое состояние и правила: генерацию подземелий, движение, бой, инвентарь, видимость и другие механики.

**Data** отвечает за сохранение и восстановление состояния игры, а также работу со статистикой.

**Presentation** обрабатывает пользовательский ввод, меню и отображение игрового мира в 2D и псевдо-3D.

Точка входа в `cmd/rogue` связывает эти компоненты.

## Сборка и запуск

### Требования

Для сборки необходимы:

- Linux или WSL.
- Go 1.24.3 или новее.
- C-компилятор и включённый CGO.
- `make` и `pkg-config`.
- Заголовки и библиотеки ncurses.
- Терминал с поддержкой UTF-8.
- Локаль `ru_RU.UTF-8`.

В Ubuntu необходимые системные зависимости можно установить командами:

```bash
sudo apt update
sudo apt install build-essential pkg-config libncurses-dev locales
sudo locale-gen ru_RU.UTF-8
```

Go устанавливается отдельно.

### Запуск игры

Клонируйте репозиторий:

```bash
git clone https://github.com/4vertak/rogue-go.git
cd rogue-go
```

Соберите проект:

```bash
make build
```

Запустите игру:

```bash
make run
```

Или запустите уже собранный исполняемый файл:

```bash
./build/rogue
```

Для удаления исполняемого файла:

```bash
make clean
```

Рекомендуется использовать достаточно большое окно терминала. Проверка запуска проводилась при размере 140 × 40 символов с `TERM=xterm-256color`.

## Управление

### Основные действия

| Действие | Клавиши |
|---|---|
| Движение в 2D | `W/A/S/D` или стрелки |
| Переключение 2D / 3D | `T` |
| Открыть инвентарь | `I` |
| Подобрать предмет | `P` |
| Оружие | `H` |
| Пища | `J` |
| Зелье | `K` |
| Свиток или ключ | `E` |
| Сохранить игру в 2D | `V` |
| Загрузить игру в 2D | `O` |
| Открыть меню выхода в 2D | `Q` |

### Псевдо-3D

| Действие | Клавиши |
|---|---|
| Вперёд / назад | `W/S` или `↑/↓` |
| Боковое перемещение | `A/D` |
| Поворот камеры | `←/→` |
| Показать / скрыть мини-карту | `M` |
| Взаимодействие | `Пробел` / `Enter` |
| Меню выхода | `Esc` |

В меню используются стрелки и `Enter`. Для выбора предметов — цифровые клавиши.

Сохранение и загрузка во время игры доступны через 2D-режим.

## Тестирование

В проекте используются стандартные средства тестирования Go.

Запуск тестов:

```bash
go test ./...
```

Статический анализ:

```bash
go vet ./...
```

Автоматические тесты охватывают работу JSON-хранилища: сохранение состояния, обработку ошибок чтения и запись игровой статистики.

Также проверены сборка, запуск, основные переходы между меню, переключение режимов отображения, открытие инвентаря, сохранение и загрузка.

### Известные ограничения

Проект сохраняет особенности учебной версии:

- Псевдо-3D остаётся экспериментальным; некоторые экранные подсказки не соответствуют фактическому управлению.
- Взаимодействие с соседними предметами в 3D работает не во всех ситуациях.
- Интерфейс рассчитан на достаточно большое окно терминала.
- Загрузка JSON не предусматривает полной проверки структуры игрового состояния.

Полное прохождение всех уровней и проверка каждой игровой механики не выполнялись.
